# 上下文窗口、证据覆盖与保真压缩

每个节点的一次模型请求采用 200,000 tokens 的本地总窗口，包含系统提示、输入、输出预留和安全余量。它不是整个 run 的累计消耗预算，也不代表供应商实际支持该容量。

## 配置与计数

`config/config.toml` 的 `[runtime.context]` 使用以下默认值：

| 配置 | 默认值 |
| --- | ---: |
| `window_tokens` | 200000 |
| `trigger_tokens` | 160000 |
| `target_tokens` | 120000 |
| `max_output_tokens` | 4096 |
| `compact_output_tokens` | 8192 |
| `safety_margin_tokens` | 4096 |

`GET /config` 在 `params.context` 返回当前策略。`POST /config/params` 接受 `{"context":{"trigger_tokens":150000}}` 这样的部分更新：先与当前策略合并并验证，再更新与重建图。配置覆盖和重置沿用原有存储流程。旧配置自动使用默认值；策略及提示词版本进入研究 checkpoint 的配置指纹。

发送前检查 `input + reserved_output + safety_margin <= window`。普通文本、结构化输出、JSON repair 和摘要调用都绑定输出上限，即使没有启用货币预算也一样。

适配器可以显式提供 `count_tokens_offline(messages)`。没有该离线能力时采用 UTF-8 字节数加消息开销的保守估计，不下载 tokenizer。它可能比模型真实 token 数大很多；内部事件中的 `context_usage.counting_method` 明确区分计数方式，`token_usage` 仍只表示供应商实际返回的使用量。费用预留继续使用既有保守口径。

每个候选模型（包括 fallback）都按自己的计数方式检查触发阈值；摘要可用预算和压缩后目标验收也使用该目标模型的计数器。摘要请求仍由节点主模型处理，并遵守主模型的请求窗口；同一输入不会因切换 fallback 再次请求摘要。内部事件中的压缩前后计数统一使用最后尝试候选的口径。

## 输入整理与摘要边界

原始 state、正文、引用与核验结果保持可追溯。角色视图只改变发送内容：同一事实通过唯一 facts 表引用，任务与 claims 使用 `fact_ids`，来源元信息单独保存。相同层级和正文 hash 的文本只发送一次并保留来源映射；转载不会自动变成独立确认。正文确切包含同来源摘要时才能省略摘要。

事实等价比较忽略由 `fact_id` 派生的 `citation_id`，但保留文档 hash、引文、偏移和验证状态；原始记录中的各个 ID 保留。合并正文时，每个来源的标题、发布时间、采集时间、正文版本和其他元信息独立保留，不用代表文档的元信息覆盖其他来源。

研究主管和合成器收到按 `side:round:claim_index` 标识的每条辩论 claim，包括完整陈述、`source_path`、`source_value`、`observed`、`verdict` 和快照版本。旧记录不能靠截断陈述或来源路径猜测匹配；有保存的 canonical 输入时重新做确定性核验，否则标记 `unknown`。

`verified` 只证明引用路径和值一致。模型论述放在 `derived_context`，不能覆盖证据状态、冲突、风险或流程限制。

两名辩手也使用同一封装：`prior_round_turns.argument_context_id` 指向 `derived_context` 中相应的上一轮论述；`structured_claims` 和 canonical 引用命名空间始终原样保留。

确定性整理后输入达到触发阈值，才用节点的主模型对明确指定的说明文字和历史论述进行一次保真摘要。事实、数值、引文、确认状态、覆盖缺口和风险字段由程序直接保留。摘要的来源 ID 必须覆盖全部输入块，JSON 结构、预算或来源验证失败时拒绝替换。

摘要提示词保留原始 faithful 模板的状态区分与更正原则，增加不可信数据边界、固定 JSON 结构、预算和 `cannot_compact_safely` 输出。摘要是派生说明，不是新的事实或验证结果；结构检查不能证明语义绝对无损。

一次输入版本最多进行一次摘要尝试，无摘要重试、JSON repair 或递归摘要。成功和失败记录均可随 checkpoint 保存，缓存键包含节点、系统提示、原输入、策略及提示词版本。后续摘要基于原材料生成，不反复压缩上一版摘要。

如果摘要失败而原输入仍能容纳，则发送原输入；原文过大由研究阅读计划分批，其他不可拆材料超限时返回节点的安全降级结果。确定性 `context_length` 错误不会按普通重试策略原样重发；尚未摘要且有可压缩材料时可尝试一次实质缩小的输入，随后仅沿用允许的 fallback。

## 阅读覆盖与两轮补读

正文分块使用精确半开区间 `[start,end)`，原文切片与 chunk text 相等；默认 8,000 字符、500 字符重叠。覆盖字符数按区间并集合计。保存全文不代表已经阅读；提交、研究成功与核验成功的区间分别记录。

每轮按照上下文预算选择分块，优先任务直接来源和官方来源，长文先覆盖首尾再补中间。最多两轮，第二轮优先补读缓存中的剩余正文，不重复抓取或增加页面尝试。新内容与前轮事实一起核验；即使没有新事实，也检查新正文是否限制或否定已有事实。核验器使用累计成功读取的原文区间，不能只用引用句周围片段宣布完整。

批次保留全量 statement、scope、numbers、uncertainty。事实合并不会覆盖前一轮结果，也不会合并相互矛盾的陈述；失败、无法容纳的核验材料和未读区间保持明确缺口。程序产生的缺口不能被模型的 `gaps=[]` 清除。

关键事件只有纳入任务阅读计划的正文全部覆盖、事实核验与确认状态满足条件后才可解除观望。普通缺口继续披露，不自动阻断所有任务。抓取失败、超大页面、抽取失败与保存文本的阅读缺口分开处理；阅读完整仅指保存的抽取文本，不能证明网页抽取没有遗漏。

## 恢复、回放与验证边界

每个事件使用 `prepare_batch → research_batch → verify_batch → finish_batch` 的可 checkpoint 子图。研究完成并持久化后中断，恢复直接进入核验，不重复已完成研究调用。调用完成到 checkpoint 提交之间仍有崩溃窗口；预算恢复沿用已有尝试记录，不承诺 exactly-once。

应用图的 replay 走独立保存结果分支，不调用模型、压缩或抓取。证据回放确定性重新检查保存引用和覆盖记录；最终支持结果仅在输入 fingerprint 匹配时复用，否则标为 `replay_verification_unknown` 并保守降级。旧记录缺失覆盖信息时标记 unknown，不从保存全文反推旧模型读过全文。缺失最终建议的记录明确返回 `no_trade`。

`run_replay` 仍支持注入自定义离线评估图；默认应用图的回放不再用于重新生成 LLM 策略。重新运行模型比较需要显式新建分析，不能借 replay 绕过调用预算。

新增回归使用 fixture、fake model 和临时目录，覆盖误标截断、重叠计数、跨轮反证、预算耗尽、摘要失败、配置往返和 checkpoint/replay。输入大小与摘要次数可通过保存的内部事件对比；合成测试不证明真实模型质量、实际费用或收益改善。
